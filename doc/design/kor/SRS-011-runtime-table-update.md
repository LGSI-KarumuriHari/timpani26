# SRS-011: Runtime Table Update — Phase 0 요구사항 명세

**작성일:** 2026-10-28  
**상태:** Draft — Phase 0 전용, 구현 완료 또는 안전 운용 승인 아님  
**상위 기준:** [REQ-011](../kor/REQ-011-runtime-table-update.md) §1.5, §7.1, §8.2, §9  
**관련 문서:** [HLD-011](HLD-011-runtime-table-update.md), [DDR-011](DDR-011-runtime-table-update.md), [LLD-011](LLD-011-runtime-table-update.md)

## 1. 목적과 적용 규칙

이 문서는 런타임 테이블 갱신의 **기본 동작 확인**에 필요한 소프트웨어 요구사항만 정의한다. 기존 PoC Level 1 및 v2.x/v3.0 문서 세트의 요구사항을 자동 승계하지 않는다. 기존 구현의 안전장치는 제거하지 않되, 후속 단계 기능을 새로 구현하는 것을 Phase 0 완료 조건으로 삼지 않는다.

요구사항 ID는 기존 SRS와 구분되는 `REQ-RTU-P0-F/N-###`을 사용한다. 아래 표의 `F-###`, `N-###`은 상위 `REQ-011-F/N-###`의 약칭이고, `AC-P0-###`은 REQ의 Phase 0 수용 기준이다. 모든 활성 항목은 이 문서 범위에서 SHALL이다. 일부 상위 요구사항의 충족은 **Phase 0 적용 부분에만 한정**된다.

## 2. 시험 경계

| 구분 | Phase 0 조건 |
|:--|:--|
| 실행 대상 | 단일 노드, 사전 지정한 하나 이상의 격리 CPU(`0..63`), L1 TT만 사용 |
| 시간 기준 | 노드 전역 양수 hyperperiod `H`와 epoch `E`를 모든 격리 CPU가 공유·유지. 시계는 안정적이고 노드 전체 TT 주기가 현재 표현으로 정확히 나타낼 수 있는 harmonic 집합을 이룸 |
| 테이블 | 태스크당 단일 격리 CPU 배정 및 유지 활성 태스크의 기존 배정 CPU 고정. 경계를 넘지 않는 슬롯과 사용 중인 모든 격리 CPU의 마지막 TT 슬롯 이후 준비/게시를 위한 충분한 공통 TT-free 여유가 있는 시험 구성. 빈 테이블도 `E`, `H` 유지 |
| 의미론적 연산 | REPLACE, ADD, REMOVE(복구 STOP 포함), CLEAR. 모두 기존 `ControlCommand.full_table`로 전달 |
| 입력 | O의 기존 입력(`AddSchedInfo`, `EnforceRecoveryPolicy(RECOVERY_STOP)`) 또는 O 내부 시험 경로에 워크로드 변경 제공. O가 생성·검증하고 N이 실행하며, N 직접 주입이나 `RecoverySignal` 단독 전달만으로 end-to-end 성공 판정 금지 |
| 요청 | O 및 N에서 노드당 한 건만 진행. 다음 요청은 앞선 결과 확인 후 제출 |
| 초기 조건 | O와 N에 동일한 기준 테이블이 확인되어 있고 태스크 등록·통신·BPF·SHM이 정상. 최초 기동 자체는 시험 대상 아님 |

UPD-MODIFY, hyperperiod/epoch 변경, 노드의 격리 CPU 구성 변경, 활성 태스크의 코어 간 이동, CBS, 복합 파이프라인, 다중 노드, 동적 CPU 공급, 정상 배포 해제용 신규 RPC는 제외한다. 기존 프로토콜 스키마, 공개 메서드 및 애플리케이션 ABI 변경은 승인 없이 허용하지 않는다.

| **REQ-RTU-P0-F-014** | REMOVE/CLEAR의 정상 완료 시 제거 대상의 TT 실행·예산 관련 항목·태스크 등록·애플리케이션 항목·내부 참조를 정리해야 한다. 조회 시 철회를 관측할 수 있어야 하며 OS scheduling policy/affinity를 변경하거나 복원해서는 안 된다. | F-032, F-040 | AC-P0-02, AC-P0-03, AC-P0-05 |

| **REQ-RTU-P0-F-018** | 활성화 도중 실패·연결 단절·결과 미확인·시계 이상으로 시험 전제가 깨지면 성공으로 판정해서는 안 된다. 시험기는 후속 제출을 중단하고 원인을 기록해야 하며, 자동 롤백·안전 정지·재동기화 성공을 가정해서는 안 된다. 기존 안전장치는 유지한다. | N-008 | AC-P0-08 |

## 5. 검증 시나리오

사전 지정한 격리 CPU 집합과 고정 `E/H` 격자에서 O가 생성한 기준 테이블 `A={W1,W2}`를 사용한다. 유지 워크로드 `W1`의 배정 CPU와 타이밍 파라미터는 고정한다. 각 시험은 알려진 기준 상태에서 시작하고, 이전 시험의 미확인 결과를 다음 시험의 기준으로 사용하지 않는다.

| 시험 ID | 입력·조작 | 관측 및 성공 판정 | REQ 기준 |
|:--|:--|:--|:--|
| **TC-P0-01** | `A`를 `{W1,W3}` 전체 스냅샷으로 대체 | `E+kH` 전환, 진행 슬롯 완료, 이전/새 테이블 혼합 없음, `W1` 배정 CPU 고정 및 실제 새 태스크 실행, 데몬/유지 앱 재시작 없음 | AC-P0-01 |
| **TC-P0-02** | `A→{W1,W2,W3}→{W1,W3}`를 한 건씩 적용(복구 STOP에 의한 제거 포함) | W1 파라미터·배정 CPU와 PID 유지, W3 가용 격리 CPU 배치 및 실행 시작, W2 디스패치 중단 및 런타임/게시 항목 정리, STOP은 상관 ACK 확인 후에만 완료 응답 반환 | AC-P0-02 |
| **TC-P0-03** | `A→빈 테이블→{W1}` 및 빈 테이블 후 REPLACE | 빈 테이블의 ID/E/H 유지, TT 디스패치·잔존 항목 없음, 후속 적용/실행 성공 | AC-P0-03 |
| **TC-P0-04** | 잘못된 노드·필드·비격리 CPU·단일 태스크 다중 CPU 분산·유지 태스크 CPU 이동·태스크·표현/용량 초과를 매개변수화. O의 생성 불가 입력도 별도 제출 | 활성화 전 거절·사유, O 확정 모델과 N 활성 테이블 불변, 후보 잔존 없음. 지원하지 않는 CBS/시간 격자 변경도 동일 확인 | AC-P0-04 |
| **TC-P0-05** | 갱신 중 TT 애플리케이션의 조회와 대기를 관측 | 유효한 이전/새 게시만 사용, 제어 wake로 잡 실행 없음, 제거 조회는 철회, 유지 앱 재시작 없음 | AC-P0-05 |
| **TC-P0-06** | O 입력(복구 STOP 포함)에서 네 결과를 생성. 한 건 준비 중 추가 요청 제출 후 앞선 결과를 확인하고 다시 제출 | 실제 O 생성/검증·기존 full_table 전송·N 실행, 추가 요청은 거절, 앞선 결과 후 다음 요청 성공 | AC-P0-06 |
| **TC-P0-07** | 정상/거절 시험의 O/N 로그·결과 수집 | 동일 node/table ID로 연결, 적용 계획 시각과 실제 시각 구분, 성공 ACK가 실제 적용보다 먼저 발생하지 않음 | AC-P0-07 |
| **TC-P0-08** | 위 정상/기본 거절 시험 반복 및 변경 RT 경로 검토 | 반복 판정 가능, 슬롯 순서 동일, 금지 연산 추가 없음. 시험 전제 이탈은 PASS가 아닌 오류/중단으로 기록 | AC-P0-08 |

시험 대기 한계와 복구 STOP 응답의 유한 ACK 대기 기한은 **호출 결과 판정 또는 시험기의 종료 조건**으로만 사용하며, 운영용 미확인 상태 전이·자동 재전송 복구 계약이나 수락-활성화 지연 보장으로 해석하지 않는다. 지터·최악 지연·잡 누락 0건·FFI·fail-safe 증명은 이 단계의 수용 기준이 아니다.

## 7. 추적성 및 후속 이관

§3·§4의 각 행은 상위 REQ와 AC-P0를 인용한다. 역방향으로 AC-P0-01..08은 §5의 TC-P0-01..08에 대응한다. HLD는 책임과 흐름, DDR은 결정, LLD는 내부 처리와 시험 접점을 명세하며 이 SRS의 활성 ID를 인용한다. 기존 요구사항 전체를 충족했다는 표시는 하지 않는다.

| 단계 | 이관 범위 |
|:--|:--|
| Phase 1 | CBS, MODIFY, hyperperiod·격리 CPU 구성 변경, 활성 태스크의 코어 간 이동, 파이프라인·코어별 타이머 확장·다중 노드 정상 동작, 요청 대기/병합/중복 정책(반복 STOP 무해 수렴 포함), 세부 앱 계약·핸들 안정성, 정량 타이밍/FFI·용량 확장·영속 감사 |
| Phase 2 | 활성화 실패·롤백·복원 실패 정지, ACK 미확인·단절/재시작 재동기화, 복구 STOP 실패 시 재디스패치 차단·기준선 재동기화, 시계 이상, 결함 감시 상태 보존, 다중 노드 부분 실패 |

이관 기능의 훅이나 일반화된 프레임워크를 Phase 0에 선행 구현하지 않는다. 구현계획 문서는 이 문서 세트에 포함하지 않는다.
