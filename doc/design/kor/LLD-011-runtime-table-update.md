## 1. 설계 경계와 기존 접점

자료 이름은 **모듈 내부의 논리적 레코드**를 뜻하며 신규 공개 클래스/API 제안이 아니다. 기존 공개 메서드와 proto/SHM 레이아웃을 유지한다. 소스 변경이나 구현계획은 이 문서의 산출물이 아니다.

| 기존 접점 | 내부 처리의 변경 의도 |

`set_schedule_table()`과 `apply_table_update()` 등 현재 void 메서드의 반환만으로 성공을 판정하지 않는다. 완료는 내부 기록의 table 문맥·경계·실제 커널 선택·게시 상태로 확인한다. 이를 위해 공개 메서드 추가가 필요해지면 구현 전에 별도 승인을 받는다.

## 2. 내부 자료와 소유권

| 논리 레코드 | 내용 | 소유·수명 |
|:--|:--|:--|
| OConfirmed | 현재 확정 모델과 전체 테이블 | O 비RT 경로. 일치한 성공 ACK 뒤에만 교체 |
| OAttempt | node/table ID, 연산/대상, 후보 모델/테이블, 진행 여부 | 노드당 1개. 전송부터 결과 처리까지 유지 |
| NPrepared | 불변 슬롯 배열(코어별 차기 슬롯 오프셋 포함), 사용 격리 CPU 마스크, 태스크별 배정 CPU·PID/해시 매핑, 제거 집합, SHM 이미지, 뱅크 번호, E/H/G/T | N 비RT 경로에서 생성. RT 사용 종료 및 구 참조 정리 전 해제 금지 |
| KernelControl | 활성 뱅크, TT 인계 게이트, 뱅크별 참조 기록 | 로드 시 준비한 정렬된 공유 제어 영역. BPF와 userspace의 atomic 접근 |
| ApplyCompletion | 준비 토큰, 적용 여부, 계획/실제 시각, 정리 결과 | RT는 고정 크기 필드만 게시. 문자열 구성·로그·ACK는 비RT 경로 |

`table_id` 문자열은 RT에서 복사하지 않는다. 준비 토큰으로 이미 만들어진 문맥을 참조한다. 슬롯 정렬 키는 `(offset_ns, cpu, workload_id_hash, task_id_hash, slot_idx)`로 고정하며 `slot_idx`는 O가 생성한 스냅샷의 위치를 따른다. 각 슬롯의 차기 시작 시각은 전체 배열의 인접 슬롯이 아니라 동일 `cpu`의 다음 슬롯(마지막 슬롯은 `H` 이후 해당 코어 첫 슬롯)을 가리킨다. 전역 생성 결과의 입력 순서 독립성까지 증명하지는 않는다.

SHM 이미지는 고유 태스크 기준으로 만든다. 유지 태스크의 인덱스와 counter는 보존하고 제거 위치의 이름은 비운다. 신규 태스크는 빈 인덱스를 사용하며 기존 대기자의 counter를 게시 사건으로 증가시키거나 초기화하지 않는다. `n_tasks`는 점유 인덱스 최댓값+1이고 CLEAR는 0이다. 매핑 충돌·해시 충돌·용량 초과는 게시 전에 거절한다.

## 3. L-P0-01 — O의 입력·후보 생성

1. 노드에 진행 중 요청이 있으면 기존 실패 경로로 거절한다. 대기열을 만들지 않는다.
2. 사전 설정된 격리 CPU 집합(`0..63`, 중복 없음)과 알려진 확정 기준의 E/전역 H 위에서 OConfirmed를 복사하고 시험 입력의 워크로드 집합을 반영한다. 확정 테이블에 존재하는 활성 태스크는 기존 배정 CPU를 그대로 고정하고, 신규 워크로드는 미사용 격리 CPU 우선(모두 점유 시 최소 부하 CPU)으로 배정한다. 동일 태스크 신원은 시험 회차 중 다른 태스크로 재사용하지 않는다.
3. 노드 전체 TT 주기에 대해 하나의 전역 harmonic hyperperiod를 산출해 모든 격리 CPU 슬롯 배치에 공통 적용하며, 기존 생성·스케줄 가능성 검증과 직렬화를 후보에 수행한다. 단일 태스크의 다중 CPU 분산, 유지 태스크의 배정 CPU 이동, ADD/REMOVE 유지 항목 변동, 변환/용량 확인 실패 시 후보를 폐기한다.
4. 비어 있지 않은 고유 table ID를 부여한다. CLEAR도 E/H/node ID와 빈 partitions를 가진다.
5. 기존 NodeStream full_table을 전송하고 OAttempt를 유지한다. 전송 성공만으로 OConfirmed를 바꾸지 않는다.
6. `EnforceRecoveryPolicy(RECOVERY_STOP)`는 대상 워크로드(식별자 또는 해시)를 해석해 같은 단일 후보 REMOVE 경로(남은 워크로드가 없으면 빈 partitions 테이블)로 등록하며 `RecoverySignal`은 보내지 않는다. 진행 중 후보 충돌·미존재 대상·검증 실패 시 즉시 실패를 반환한다. 후보가 등록되면 유한 대기 기한(5 s) 내에 해당 시도의 결과 정착을 기다려, 확정 모델에서 대상 제거가 확인된 경우에만 성공을 반환하고 세션을 유지한다(사전 거절·세션 중단·기한 초과 시 실패 반환).

**P0-T01 연결 승인 (2026-10-29):** 기존 경로는 보존하며 `--runtime-table-update-phase0`에서만 이 계약을 적용한다.
`SchedInfoServer::EnablePhase0`와 `PushPendingTables` 두 연결 메서드의 추가가 승인되었다. 활성화는 서비스 시작 전에 수행하고, 기존 main 비RT 루프가 미전송 후보를 한 번만 전송한다. ACK/단절 콜백은 내부 상태의 수명을 공유한다. 전송 전에 후보의 송신 여부를 기록하고 락을 해제하므로 `Write` 반환 전 ACK도 처리할 수 있다. 최초 연결 대기 중에도 후보는 한 건이며 후속 요청은 저장하지 않는다.

추가될 시험 프로세스도 미리 생성·등록·대기 가능해야 한다. 테이블 갱신 중 policy/affinity를 변경해서 로컬 준비를 보완하지 않는다. 시험 준비는 기존 노드/워크로드 기동 절차를 사용하고 애플리케이션이 커널 속성을 스스로 설정하게 하지 않는다.

## 4. L-P0-02 — N의 사전 확인·거절

| 확인 항목 | 처리 |
|:--|:--|
| 수신 문맥 | 현재 인가된 연결과 대상 node ID, 비어 있지 않은 table ID 확인 |
| 진행 중 후보 | 한 건 준비/인계/정리 중 추가 명령은 상태 변경 없이 실패 응답 |
| 시험 범위 | TT만 허용. CBS·비TT 모델·단일 태스크의 다중 CPU 분산·유지 태스크의 CPU 이동·기준 E/H 변경·델타 경로 거절 |
| 유지 워크로드 | 활성 기준의 전체 슬롯 파라미터(태스크, offset/duration/deadline, CPU, current_limit, layer)와 반복 수 보존. 입력 순서·slot_idx만 달라진 경우는 허용하며 태스크 구성 변경은 거절 |
| 값/표현 | 양수 H, 시간의 무손실 ns 변환, 합산/경계 계산 overflow, 슬롯의 `[0,H)` 범위 확인 |
| 로컬 참조 | 사용 CPU 전체의 격리 CPU 마스크(`0..63`) 포함 여부, 태스크 이름/PID의 유일성·생존, 식별자와 해시의 일관성 |
| 용량 | 실제 빌드의 TT 맵/태스크 맵/SHM 최소 상한. 고유 태스크와 반복 슬롯 수는 따로 계산 |

N은 슬롯 쌍의 중첩 검사·CPU 재배치·스케줄 가능성 분석을 수행하지 않는다. 시간 범위·형식이 맞더라도 스케줄 가능성 책임은 O에 있다.

이 단계에서는 활성 workload 추적 맵·BPF 설정·SHM을 삭제/덮어쓰지 않는다. 준비 실패 시 후보 전용 등록/맵만 되돌려 폐기하고 기존 모델/실행/게시가 불변인지 확인한 뒤 `success=false`와 사유를 보낸다. 적용 게이트를 닫은 이후의 오류는 이 사전 거절 보장으로 보고하지 않는다.

**P0-T02 연결 승인 (2026-10-29):** N도 `--runtime-table-update-phase0`에서만 이 확인을 적용하며 기본 경로는 유지한다. `NodeClient`와 공개 API는 바꾸지 않고 기존 콜백으로 `full_table`을 시도 1건에 등록한다. 사전 확인과 `NPrepared` 조립은 내부 모듈 `phase0_prepare`가 기존 main 비RT 루프에서 수행한다. 격리 CPU 마스크는 이 모듈이 시작 시 cgroup v2에서 한 번 읽는다. 통과한 후보는 P0-T03..T06 전까지 기존 즉시 적용 경로로 인계하므로, 이 기간에는 §6~§8의 경계 전환·SHM 게시 계약이 아직 성립하지 않는다.

## 5. L-P0-03 — BPF 비활성 준비와 참조 수명

TT 슬롯과 TaskMeta(각 태스크의 `assigned_cpu`는 해당 태스크 레코드의 배정 CPU로 설정)의 두 뱅크는 동일 활성 선택자를 사용한다. 기존 구조체는 유지하되 BpfLoader의 후보 쓰기 대상과 BPF의 조회 대상을 실제 뱅크에 연결한다. 현재 사용자 인덱스 토글만 있는 메서드는 불충분하다.

- 비RT 준비자는 비활성 뱅크가 RT 컨텍스트에서 사용되지 않고 커널 참조가 0인 경우에만 지우고 채운다. 확인할 수 없으면 활성 상태를 건드리지 않고 준비를 완료하지 않는다.
- BPF 처리 구간은 선택자를 읽고 해당 참조를 확보한 뒤 선택자/게이트를 재확인한다. 바뀌었으면 그 뱅크의 데이터를 사용하지 않고 참조를 반환한다. 성공한 구간은 슬롯·메타데이터를 같은 뱅크에서 읽고 모든 종료 경로에서 참조를 반환한다.
- 코어별 실행 가능 TT 태스크 카운트(`tt_runnable_count_map`)는 64비트 원자적 증감으로 관리하며 enqueue와 stopping 모두 태스크의 배정 CPU를 기준으로 계수한다.
- TT 인계 게이트가 닫혔을 때는 후보 또는 이전 TT 작업을 새로 실행시키지 않는다. 깨어난 TT 태스크는 `SCX_DSQ_GLOBAL`을 통해 형제 격리 CPU로 분산되지 않도록 자기 배정 CPU의 로컬 DSQ(`SCX_DSQ_LOCAL_ON | assigned_cpu`)에 비선점으로 적재하며, 관련 select/enqueue/dispatch 경로 전체에서 같은 규칙을 사용한다.
- 새 뱅크의 TT 가변 필드는 새 실행에 맞게 준비하되 활성 뱅크의 `tt_runnable/activation_ns`를 준비 과정에서 초기화하지 않는다. 실제 실행 가능 상태로 진입할 때 `activation_ns`를 기록하고 실행 가능 TT 잡에 대해서만 배정 CPU 기준 데드라인 미스를 판정한다. 실행 중 태스크가 없는 TT-free 인계에서만 구 실행의 종료를 확정한다.
- 경계 인계 후 구 타이머 컨텍스트와 커널 참조가 끝났으면 비RT 경로에서 구 뱅크·제거 등록을 정리한다. 완료 전 다음 요청을 수락하지 않는다.

참조 확보/재확인/정리 사이의 메모리 순서는 target BPF/userspace 시험으로 검증한다. 공유 제어 영역은 로드 시 준비하고 필요한 atomic 지원·정렬을 사전 확인한다. 새 의존성이나 공개 ABI를 만들지 않는다. CBS 런타임 상태, 결함 감시 상태의 새 보존 알고리즘, 일반 은퇴 상태 기계는 도입하지 않는다.

## 6. L-P0-04 — 고정 격자의 경계 인계

`H_ns = uint64(hyperperiod_us) * 1000`을 확인된 범위에서 계산한다. 후보 준비 시각보다 미래이며 구 TT 슬롯을 모두 완료할 수 있는 `T = E + k * H_ns`를 선택한다. 계산 overflow나 유효한 격자를 만들 수 없는 입력은 활성화 전에 거절한다.

| 구간 | 담당·행동 | 불변 조건 |
|:--|:--|:--|
| 인계 전 | 비RT에서 NPrepared·비활성 BPF·SHM 이미지 준비 | 활성 실행/게시 불변. 늦으면 이후 경계를 선택 |
| 구 슬롯 완료 G | 상주 타이머가 모든 격리 CPU의 마지막 슬롯 완료와 인계 가능을 atomic 기록 | 관여하는 어느 CPU에라도 진행 TT 작업·대기 실행이 남거나 구 참조가 남아 있으면 완료 아님 |
| `[G,T)` | 비RT에서 관여하는 모든 격리 CPU(`active \| next` 마스크)의 TT 유휴 및 게이트 닫힘 확인, SHM 세대 무효화/이미지 기록, 새 BPF 뱅크 선택, 관여 CPU별 현재 슬롯 `SLOT_NONE` 및 해당 코어 첫 발화 시각(슬롯이 없으면 유휴) 초기화 | 모든 관여 CPU에 구 TT 작업 없음, 후보 TT 실행 없음, 새 SHM은 아직 유효하지 않음 |
| 경계 T | RT가 준비 완료 토큰을 acquire 확인하고 새 컨텍스트 선택, 짝수 세대/magic 유효화, TT 게이트 해제 | 실제 발화 전 커널/타이머/앱 모두 같은 후보. 추가 작업은 고정 개수 메모리 연산 |
| 경계 이후 | 새 슬롯 발화, 완료 기록을 비RT로 전달, 구 항목 정리·결과 확인 | 성공 ACK는 이 확인보다 앞서지 않음 |

SHM 데이터 복사·BPF 맵 갱신·태스크 탐색·정렬·스레드 생성/join·정리·문자열 로그는 RT에서 수행하지 않는다. RT의 경계 유효화는 로드 시 확보한 공유 제어 값의 atomic store로 처리한다. 실제 슬롯 발화에 필요한 기존 제어 경로도 후보/활성 뱅크 일관성을 유지해야 한다.

인계 시작 후 준비가 경계에 미치지 못하면 성공으로 처리하지 않는다. 이는 시험 전제 실패이고 임의 시각에 적용하거나 새 epoch로 재시작하지 않는다. 자동 복원·재시도는 설계하지 않는다. 시험기의 중단이 제품의 안전 정지를 보장한다고 해석하지 않는다.

CLEAR는 빈 컨텍스트를 같은 방식으로 활성화한다. 상주 루프는 H 격자에서 슬롯 없이 대기하며 후속 ADD/REPLACE를 처리한다. 이미 실행한 마지막 태스크는 완료시키고 TT 메타데이터/추적 항목을 정리하되 policy/affinity는 변경하지 않는다.

**P0-T04 연결 승인 (2026-11-02):** 인계 규칙은 내부 모듈 `phase0_handover`에 두고, TimerMaster가 실제 커널·SHM 접점을 연결한다. 조정자는 T까지 1 ms 이상 남았을 때만 commit을 게시하며, 게이트를 닫기 전후에 TT runnable과 활성 뱅크 refs를 확인한다. 정지 상태를 확인하지 못하면 최대 8개 경계까지 미룬 뒤 적용 전에 거절한다. RT 스레드는 경계마다 인계 상태를 확인하고, 준비된 후보를 고정 개수의 atomic 연산으로 전환한다. commit 후 T까지 준비되지 않으면 실패로 기록하고 발화를 멈춘다. 공개 메서드는 `TimerMaster::enable_phase0`·`apply_phase0_table`과 `BpfLoader::kernel_control`·`tt_runnable_count`·`select_staged_bank`의 추가가 승인되었다. main 비RT 루프 연결과 구 상태 정리는 L-P0-06(P0-T06)에서 한다.

## 7. L-P0-05 — SHM 게시·읽기·대기

### 7.1 작성자

1. 비RT 준비에서 새 이미지와 인덱스 매핑을 완성한다. 안정 세대 `g`는 짝수이고 `g+2`의 overflow를 사전 확인한다.
2. TT-free 인계에서 `generation=g+1`과 `magic=0`으로 게시 중임을 알린다. 쓰기 순서를 보장한 뒤 이름·n_tasks 등 메타데이터를 기록한다.
3. counter는 유지한다. 제거된 이름은 비우고 신규 이름은 고유하게 배치한다. 게시 때문에 전체 counter를 증가시키거나 전체 futex wake를 하지 않는다.
4. BPF/타이머 준비가 끝난 경계 T에 RT가 `generation=g+2`와 유효 magic을 release 순서로 게시한다. 그 후에만 TT 발화를 허용한다.

초기 공통 게시 경로도 유효한 짝수 세대를 사용한다. 초기 기동 시험을 새로 요구하는 것이 아니라, 런타임 소비자가 해석할 수 있는 기준 게시를 만드는 조건이다.

### 7.2 소비자

- 조회는 acquire 순서의 세대/magic 확인, 필요한 필드의 atomic 복사, 마지막 세대/magic 재확인으로 한다. 양쪽이 같은 안정 세대일 때만 사용한다. 공유 필드 복사를 일반 memcpy/volatile만으로 안전하다고 가정하지 않는다.
- 무효·홀수·세대 변화면 부분 값을 버린다. 기존 `-1`/재확인 계약을 사용하고 무한 busy-spin하지 않는다. 지속 무효의 수치 보장은 Phase 1 대상이다.
- futex 대기 전 자기 태스크 신원·인덱스·counter를 기록하고 대기 후 다시 유효 게시를 해석한다. 제거됐으면 `-1`, 다른 태스크의 위치로 재사용됐으면 그 wake를 소비하지 않는다.
- futex의 성공 반환·EAGAIN만으로 잡이라고 판정하지 않는다. 자기 태스크의 실제 counter 변화가 확인돼야 0을 반환한다. 게시/신호로 깼지만 counter가 그대로이면 실제 잡을 기다린다.
- 유지 태스크의 실제 슬롯이 세대 변경과 겹친 경우도 무조건 잡을 만들어내지 않는다. 같은 태스크/카운터의 실제 발화를 확인한다. 첫 잡 무손실의 일반 보장은 Phase 1 검증 대상이다.

현재 ABI의 0은 실제 잡, -1은 실행하지 말고 재확인하는 결과로 유지한다. 갱신된 libttsched와 N을 함께 사용하는 시험 구성을 기록하며 구 소비자가 이 규칙을 충족한다고 가정하지 않는다.

**P0-T05 소비자 연결 승인 (2026-11-02):** 작성자·소비자 규칙은 설치하지 않는 내부 헤더 `sample-apps/src/ttsched_shm.h`에 둔다. 이 헤더는 홀짝 세대 게시, 바이트 단위 이름 복사, 전후 세대 재확인, wake 판정을 담당한다. futex 대기는 함수로 주입한다. 앞선 snapshot과 같은 위치에서 자기 counter가 정방향으로 증가한 경우만 잡이다. 위치가 바뀌었거나 counter가 그대로·초기화된 경우는 다시 대기한다. 무효 게시와 미게시(제거·CLEAR)는 `-1`이다. 기존 TimerMaster 공통 게시도 같은 세대 규칙을 사용한다. 다만 §7.1의 counter 미증가 게시와 경계 T 유효화가 적용되기 전에는 기존 게시 wake가 남아 있다.

## 8. L-P0-06 — 제거·결과 완료

제거 집합은 이전/후보 워크로드·태스크 집합의 차이로 비RT에서 계산하며, 복구 STOP도 별도 `RecoverySignal` 직접 삭제 없이 동일한 단일 `full_table` 시도와 경계 정리 절차를 따른다. 정상 인계 후 구 참조가 끝나면 TT 항목, 태스크 메타데이터/등록, workload 추적, 앱 항목, 후보 전용 참조를 정리한다. 유지 항목은 삭제 후 재등록하지 않는다. 컨테이너를 종료하거나 policy/affinity를 복원하지 않는다.

비RT 결과 처리는 같은 준비 토큰의 실제 인계 완료, 선택된 뱅크/컨텍스트, 유효 SHM 세대 및 제거 정리를 확인한다. 확인 후 기존 `send_table_applied(table_id, true, error)` 경로를 사용한다. error의 신규 와이어 코드 규약은 만들지 않는다.

O는 현재 node/table ID에 일치하는 결과만 확정에 사용한다. 사전 거절이면 후보를 버리고 확정 상태를 유지한다. 전환 후 오류·불일치 ACK·단절·미확인은 시험 오류로 기록하고 후속 제출을 막는다. 이전 상태 복원이나 자동 수렴을 암묵적으로 가정하지 않는다.

**P0-T06 연결 승인 (2026-11-02):** 시도 순서와 ACK 판정은 내부 모듈 `phase0_attempt`에 두고, main이 TimerMaster·BpfLoader·SHM·FaultMonitor 접점을 port로 연결한다. main 비RT 루프는 사전 확인 뒤 `apply_phase0_table`로 경계 적용을 기다린다. 이어서 활성 뱅크 변경, 이번에 게시한 짝수 SHM 세대와 magic, `actual_apply_ns ≥ T`를 확인한다. 구 뱅크는 참조가 끝나면 통째로 비우며, 1 ms 간격으로 최대 100 ms까지 재시도한다. 추적 맵은 새 테이블로 다시 만들고, FaultMonitor는 기존 전체 테이블 규칙대로 초기화한 뒤 새 한도를 넣는다. 이 단계가 모두 끝난 뒤에만 성공 ACK를 보낸다. 활성 상태를 바꾸기 전의 거절은 사유와 함께 `success=false`로 보고한다. 인계 시작 후 실패·확인 실패·정리 시간 초과는 ACK와 복원 없이 `trial_failed`로 기록하고 N 연결을 끊는다. 시도는 busy로 남고 O는 단절로 시험을 중단한다.

## 9. L-P0-07 — 락·메모리·자원 규율

| 경로 | 허용 | 금지 |
|:--|:--|:--|
| 비RT 생성/준비/정리 | 기존 직렬화·락, 벡터/맵 준비, BPF 갱신, 자원 정리 | 활성 구조의 선행 파괴, 락 보유 중 경계 완료 대기 |
| RT 경계/슬롯 | 사전 준비 자료의 읽기, 고정 크기 atomic 게시, 절대 시각 대기·기존 발화 | 동적 할당·join·gRPC·파일 로그·무한 탐색/재시도·블로킹 락 |
| 애플리케이션 | 기존 futex 대기, 유효 조회, 무효 시 비발화 | 게시 알림을 실제 잡으로 간주 |

기존 `TimerMaster`의 lifecycle 락이 필요하면 schedule 락보다 먼저 획득하며 둘 다 RT 루프에 가져가지 않는다. 스케줄링 결정을 가로질러 락을 보유하지 않는다. 경계 대기는 준비/추적 락을 놓고 수행한다. 공유 원자 값은 정렬·크기·획득/해제 순서를 명시해 구현하고 target에서 검증한다.

고정 후보 1개·설정 2뱅크·현재 SHM 상한만 사용한다. 제거/실패 후 자원을 반환하는 기본 정상 계약을 검증하되 장시간 누수/용량 확장·우선순위 역전의 전면 분석을 선행 과제로 추가하지 않는다.

## 10. L-P0-08 — 시험 접점과 추적

단위 시험은 O 후보 분리, N 사전 확인·무부작용 거절, 정렬/시간 계산, SHM 세대/제어 wake, 결과 상관관계를 다룬다. BPF stub이나 N 직접 주입만으로 전체 성공을 선언하지 않는다. 목표 하드웨어 시험은 O의 실제 생성/전송과 N의 BPF/타이머/app 실행을 포함한다.

시험 로그에는 준비/인계/실제 완료 토큰과 table ID, 계획 경계, 실제 완료 시각, 뱅크/세대, 태스크 PID/발화, 사유/결과를 연결한다. RT는 준비된 기록 슬롯만 갱신하고 파일 출력은 비RT에서 한다. 시험별 시작 기준을 재확인하고 유한 시험 대기 한계를 기록한다. 하드웨어 검증이 수행되지 않았다면 별도 미검증으로 표시한다.
